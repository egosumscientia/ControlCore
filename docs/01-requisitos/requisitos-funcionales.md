## 1. Propósito

Este documento constituye el registro de los requisitos funcionales de ControlCore.

Los requisitos funcionales describen comportamientos observables que el producto deberá realizar en condiciones definidas.

## 2. Alcance

Este registro comprende exclusivamente requisitos funcionales identificados con el prefijo `RF-###`.

No comprende requisitos no funcionales ni restricciones, que se registran en:

- `docs/01-requisitos/requisitos-no-funcionales.md`
- `docs/01-requisitos/restricciones-sistema.md`

No se ha definido ningún requisito funcional. No se ha asignado ningún identificador `RF-###`. La línea base de gestión de requisitos está aprobada; no existe una línea base de requisitos funcionales concretos.

## 3. Convenciones

Se aplican las convenciones comunes de `docs/01-requisitos/README.md` (sección 3).

- Prefijo: `RF-###`.
- El identificador es único, estable y no reutilizable.
- La versión del contenido es independiente del identificador.
- No se asigna un identificador hasta que exista un requisito funcional definido y registrado.
- Se aplican las convenciones de prioridad y trazabilidad de `docs/01-requisitos/README.md` (secciones 3 y 5).
- La versión de este documento es independiente de la versión de cada requisito individual.
- Las referencias documentales utilizan rutas relativas a la raíz del repositorio.

## 4. Estructura de registro

La ficha normalizada y la obligatoriedad de cada atributo se definen en `docs/01-requisitos/README.md` (sección 4).

## 5. Estados

Se aplica el ciclo de vida y las transiciones definidos en `docs/01-requisitos/README.md` (sección 5).

La aprobación corresponde al responsable del proyecto. No se establecen aprobaciones automáticas.

## 6. Criterios de calidad

Además de los criterios generales de `docs/01-requisitos/README.md` (sección 6), cada requisito funcional deberá:

- Describir un comportamiento observable.
- Identificar entradas, salidas y condiciones de operación cuando corresponda.
- Definir límites y comportamiento ante condiciones de error cuando sean relevantes.
- Evitar imponer una solución de diseño, tecnología o implementación no aprobada.
- Disponer de un criterio de aceptación objetivable y de un método de verificación.
- No duplicar ni contradecir otros requisitos.
- Ser trazable hacia su origen y hacia su verificación.

No se aprobarán requisitos funcionales que dependan de decisiones técnicas todavía no aprobadas.

## 7. Trazabilidad

Se aplica el mecanismo de trazabilidad de `docs/01-requisitos/README.md` (sección 7).

Cada requisito funcional deberá permitir relacionar, cuando corresponda:

**Necesidad del producto → `RF-###` → Decisión → Elemento de arquitectura → Implementación → Prueba → Evidencia.**

No existen todavía vínculos registrados porque no se han definido requisitos ni elementos de arquitectura, implementación, prueba o evidencia.

Los vínculos se registrarán como **Existente**, **Pendiente** o **No aplica** según el índice común. No se presupone que todos los elementos existan.
